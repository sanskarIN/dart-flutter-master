# Gumroad Product Guide

Official storefront:

## 🛒 **https://ramsandesh.gumroad.com**

This guide defines a maintainable product structure for **Dart & Flutter Full Mastery** without committing paid publication files to GitHub.

## Recommended products

### 1. Complete Master Edition — Reader

Suggested files:

- `Dart_Flutter_Full_Mastery_Complete_120_Part_Master.pdf`
- `Dart_Flutter_Full_Mastery_Complete_120_Part_Master.epub`
- sample/preview material when useful

Best for readers who want the full 120-part book without companion source-code bundles.

### 2. Complete Master Edition — Builder

Suggested files:

- complete PDF
- complete EPUB
- companion source-code ZIP
- selected README/setup documentation

Best for readers who want both the book and hands-on companion projects.

### 3. Six-Volume Collection

Suggested delivery:

- Volume 1 — Parts 001–020
- Volume 2 — Parts 021–040
- Volume 3 — Parts 041–060
- Volume 4 — Parts 061–080
- Volume 5 — Parts 081–100
- Volume 6 — Parts 101–120

Use this when smaller downloads or topic-grouped reading are preferable.

### 4. Complete Publication Bundle

May include the complete reader formats, six-volume set, companion code, selected publication extras, checksums, and clearly documented update/version information.

## Listing metadata

Every listing should keep these references consistent:

- **Author:** Ram Sandesh
- **GitHub companion repository:** https://github.com/sanskarIN/dart-flutter-master
- **Storefront:** https://ramsandesh.gumroad.com
- **Reader/project contact:** sanskarin@outlook.in

Do not use a changeable social-profile URL as required permanent publication metadata.

## Versioning

When replacing product files:

1. Freeze the publication version.
2. Validate the source/code release where applicable.
3. Confirm the PDF/EPUB opens correctly.
4. Review `CHANGELOG.md` and `ERRATA.md`.
5. Replace the existing Gumroad product files when the same product/edition is being revised.
6. Clearly label a genuinely new edition when compatibility or content changes justify it.
7. Test buyer download delivery after the update.

Public code and errata should continue to point back to the canonical GitHub repository.
